# QrDrop

**用一块屏幕和一个摄像头传文件。**

发送端把文件编码成滚动播放的二维码序列，接收端用手机摄像头对着屏幕连续扫描，还原出原始文件。全程不碰网络、蓝牙、配对，也不需要 U 盘——只要对方能看见你的屏幕，文件就能过去。

适用于物理隔离网络、禁止外接存储的机房、临时借用的陌生电脑，以及任何"能看见但连不上"的场景。

## 特性

- **单向光学信道**。没有握手，没有回传，接收端不需要向发送端确认任何东西。
- **喷泉码传输**。发送端持续发出编码块，接收端收够任意数量即可还原，不存在"这一帧丢了要重发哪一块"的问题。丢帧代价严格线性——50% 丢帧只是时间翻倍，不会陷入长尾。
- **随时换档不丢进度**。传输途中放大或缩小二维码密度，接收端已经收到的数据继续有效，不用从头再来。
- **断点续传**。两端各自持久化进度，中途关掉重开，从上次的位置接着推、接着收。
- **多文件并发**。接收端同时维护多个会话，扫哪个是哪个，互不干扰。
- **极简发送端**。Web 版是一个双击就能打开的 HTML 文件，零依赖零安装，连 IE10 和 Android 4 都能跑。
- **紧凑帧格式**。20 字节二进制帧头，无 JSON 无 Base64，单帧有效载荷率达 99.2%。

## 怎么用

### 一、启动发送端

**Web 版**（推荐，任何设备都能用）：双击 `sender/web/index.html`，浏览器里选择要传的文件即可。

**桌面版**（Java，支持流层压缩）：

```bash
mvn -o -f sender/java/pom.xml clean package
java -cp sender/java/target/classes:<zxing jar> org.file.qrcode.QRCodeGeneratorGUI
```

不带参数启动会弹出文件选择框，支持多选，每个文件是一个独立会话。

### 二、对焦

选好文件后先进入对焦阶段——屏幕上显示一帧静止的二维码，用来让接收端从容取景、对准、合焦。建议此时把发送端切到全屏（纯白背景、无边框），识别率明显更好。

### 三、开始播放，用手机扫

发送端点播放，二维码开始滚动。接收端打开 QrDrop iOS App，点"摄像头扫描"，对准屏幕即可。进度条会实时显示收了多少。

收满之后在 App 里点击该会话，还原出文件，然后通过系统分享保存或转发到任何地方。

### 调参建议

发送端有两个旋钮，配合接收端的扫描帧率使用：

| 旋钮 | 建议值 | 说明 |
|---|---|---|
| **显示间隔** | 75–100 ms | 太快会超出摄像头的采样能力，接收端会漏帧 |
| **档位** | 从中间档试起 | 档位越高单帧信息越多，但对屏幕素质、距离、对焦要求也越高 |

接收端可调分辨率（720p / 1080p，默认 720p）与帧率上限（5–30 fps，默认 20 fps）。经验法则：**显示间隔 × 帧率 / 1000 ≥ 2.5**，即每个二维码至少被扫到 2.5 次；并尽量避开整数比，防止相位锁定导致某些帧永远扫不到。

传大文件时如果屏幕素质好、距离近，可以提高档位；反之如果进度推进缓慢，先降档位、再放慢显示间隔。

## 项目结构

```
QrDrop/
├── protocol/     协议契约、Python 参考实现与跨语言测试向量
├── sender/java/  桌面发送端（Java Swing）
├── sender/web/   Web 发送端（纯原生 HTML + JS，零依赖）
└── receiver/     接收端（iOS，SwiftUI + Vision）
```

三端共用一份协议，逐位比对同一套测试向量，任意发送端都能配任意接收端。
